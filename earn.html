Reward model

Fairness by accounting,
not by promises.

Every accepted share is hashed, reconciled, and paid according to the active split mode. Advertising a 50/50 market condition before equal work exists would be misleading.

Default

Proportional mode

reward_i = valid_share_i / total_valid_shares x net pool reward

The person who contributed more accepted work receives more of the settlement. This is the only economically honest default across unequal devices.

Optional experiment

Equal peers mode

reward_i = 1 / active_peers x net pool reward

Only viable with explicit cohort enrollment, equal or randomized assignments, anti-free-rider checks, and visible opt-in terms. It is not the universal pool rule.

Cost reality

Net rewards matter

net = gross - electricity - hardware wear - pool fee

Electricity and depreciation are real costs. Any honest mining page reports net, not gross advertising.

System architecture

The pool has one job:
verified work in, auditable credit out.

BlueHound can explain status and block unsafe work, but it cannot sign transactions, override consent, or turn a demo share into real funds.

  1. 01

    Authenticate opt-in

    Node starts only after the operator grants capacity, time window, and allowed task classes.

  2. 02

    Assign work package

    Coordinator gives a job, difficulty, deadline, nonce range, and payout basis.

  3. 03

    Compute locally

    CPU or GPU runs the job. Browser mode uses Web Crypto; native nodes can use optimized kernels.

  4. 04

    Verify share

    Validator rehashes submission and checks the proof condition. Invalid work earns zero.

  5. 05

    Ledger and reconcile

    Accepted shares, missed deadlines, duplicate proofs, and device performance are recorded.

  6. 06

    Settle

    Payout runs only after reconciliation and operator-approved destination confirmation.

Consent to run the local workload demo

Before anything hashes, here is exactly what will happen on this device:

  • Your CPU hashes SHA-256 in pooled Web Workers (hardware-accelerated where your browser/CPU supports it). You choose CPU, balanced 50/50, or GPU-labelled lanes; GPU falls back to CPU with a visible notice.
  • No pool connection, no wallet, no keys, no funds, and no network requests leave this page. Work is verified locally and the ledger is illustrative only.
  • You can stop instantly with the Stop button or by closing this tab. Closing the tab ends all work; nothing persists in the background.
  • Consent is remembered for this origin only and can be withdrawn at any time with the "Withdraw consent" button.
  • Share claims are signed with Ed25519 as a classical authenticator; post-quantum signatures (ML-DSA / FIPS 204) are a labelled roadmap item, not a current claim.

This is a local demonstration, not an investment offer, not a cryptocurrency offering, and not a guarantee of earnings. Electricity and device wear are real costs. Do not run this on a device you do not own or without the owner’s permission.
