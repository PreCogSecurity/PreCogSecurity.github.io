Methodology

How the head-to-head is measured

Static, protocol-based, and evidence-grade. Every metric here measures a dimension rivals market differently, so they are listed with their definition.

Finding counts

Total confirmed, high-confidence, verified-exploit findings on the target â€” every finding has a working exploit (see evidence bar). Measured with PreCog Security's own agents + CodeQL on the target's default query packs.

False positives

Of the candidate findings (raw signals), the fraction confirmed with a working exploit + patch. rivals publish fuzz-positive counts; we publish verified counts â€” the ratio is reported from both.

Time to verified finding

Time from first signal to a finding with a working exploit + patch (median, on the target).

Detection shipped

How many of the verified findings left a shipped detection rule (Sigma/YARA) that catches the class again, plus the rules' test coverage.

Regression test shipped

How many verified findings left a regression test proving the fix stays fixed (runs on CI).

Coverage (attack surface classes)

Which classes the scanner covered: auth bypass, injection, SSRF, deserialization, RCE, logic bugs, secrets, crypto, etc. vs. the target.

Target

The public target (as of 2026-11-19)

A public repo with CI, real code, no secrets committed (ethics-grade target).

  • TargetPreCog Security: verified findings with exploit, patch, detection, regression â€” the repo itself
  • Primary targets for comparisonSemgrep (Code Security for Builders and Agents), CodeQL (open-source security queries), OWASP ZAP (baseline).
  • Why this targetPublic, CI-backed, no secrets committed, complex security posture (web, crypto, wallet, rabbitmq, nginx configs). Large surface: ~450 lines SQL, TLS/RSA, admin panels, secret scanning targets.
Evidence bar

The evidence every finding ships with

All metrics above require proof of the finding: repro steps + a working exploit + the patch + detection + regression. Rival tools publish alerts; we publish verified work.

Exploit proof

A working PoC: run against a local build, show the effect. No "would allow" language without a demo.

Patch diff

The fix as a git diff, in the target repo, mergeable.

Detection rule

Sigma/YARA rule matching the finding class, with test coverage proof.

Regression test

Test that fails pre-fix, passes post-fix, runs on CI.
